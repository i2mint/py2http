py2http.auth

py2http.auth¶

Framework-independent credential checks, shared by the aiohttp middleware (py2http.middleware) and the Bottle plugins (py2http.bottle_plugins), so that both refuse the same tokens and keys for the same reasons.

>>> bearer_token('Bearer abc'), bearer_token('bearer abc'), bearer_token('Basic abc')
('abc', 'abc', '')
>>> key_matches('k-123', 'k-123'), key_matches('k-12', 'k-123'), key_matches(None, 'k')
(True, False, False)

class py2http.auth.AuthPlugin[source]¶

Bases: object

What a plugin must be to guard a Flask app (see py2http.flask_plugins): a subclass with a challenge (the WWW-Authenticate value of a refusal) and an authenticate that raises CredentialsRejected to refuse a request. It is a marker class rather than a duck-typed method name, so that a plugin which merely has some authenticate method (returning False to refuse, say) can’t be mistaken for one and let everything through.

py2http.auth.jwt_algorithms(secret, *, verify=True, algorithms=('HS256',), allow_mixed_algorithm_families=False)[source]¶

Validate a JWT verification setup, returning the algorithms as a list.

Raises at construction time, rather than accepting forgeries at request time, when:

  • algorithms is empty, a bare string, or names an unknown or unsigned (none) algorithm (PyJWT names are case-sensitive);

  • verify is True and secret is empty (an empty HMAC secret lets anyone sign tokens), or an HMAC algorithm is asked for with a non-str/bytes secret;

  • verify is True and HMAC and public-key algorithms are mixed with one secret (the classic algorithm-confusion setup), unless allow_mixed_algorithm_families is True.

>>> jwt_algorithms('s3cret')
['HS256']
>>> jwt_algorithms('', algorithms=['HS256'])

  ...
ValueError: secret must be a non-empty key when verify=True
